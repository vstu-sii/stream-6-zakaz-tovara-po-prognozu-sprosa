# stream-6-zakaz-tovara-po-prognozu-sprosa
2026, 6 курс · Заказ товара по прогнозу спроса

## 1. Описание проекта

**Проблема.** Директор небольшого продуктового магазина у дома заказывает
товар раз в неделю «по прошлой неделе плюс интуиция». Обе ошибки стоят денег:
пустая полка - упущенная выручка, лишний скоропорт - списание. При этом у
директора нет ни времени, ни инструмента, чтобы считать прогноз спроса.

**Решение.** AI-система считает прогноз по истории продаж с учётом сезонности,
промо, праздников и локальной специфики магазина, переводит прогноз в заказ
по кратности упаковки и сроку годности и объясняет цифру: почему на этой
неделе больше. Заказ уходит черновиком - подтверждает человек, и его правки
становятся материалом для следующего прогноза.

**Целевая аудитория.** Директор магазина у дома: 1–3 кассы, площадь 100–400 м²,
ассортимент 1 500–4 000 SKU, из них 30–40% - скоропорт. Заказ делает сам,
формализованный цикл - раз в неделю (с разной частотой по категориям).

Подробнее - в [PRD](docs/prd.md).

## 4. Архитектура

_Заполняется будущих работах

Планируется:
- **Backend:** Python-сервис
- **Frontend:** адаптивный веб-интерфейс (мобильная версия обязательна -
  требование из интервью).
- **AI pipeline:** статистический прогноз (сезонность + тренд + праздники +
  промо) + LLM для генерации объяснения.
- **DevOps:** Docker Compose, GitHub Actions CI, публичный dev-URL.


## 5. Установка и запуск

### Требования

- Docker 24+
- Docker Compose v2 (команда `docker compose`, не `docker-compose`)

### Запуск dev-среды

```bash
# 1. Клонировать репозиторий
git clone https://github.com/vstu-sii/stream-6-zakaz-tovara-po-prognozu-sprosa.git
cd stream-6-zakaz-tovara-po-prognozu-sprosa

# 2. Настроить окружение
cp .env.example .env

# 3. Поднять приложение
docker compose up -d
